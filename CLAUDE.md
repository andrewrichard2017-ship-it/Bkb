# Working on this repo

More than one person edits this game, sometimes with other AI tools (e.g. ChatGPT) or directly on GitHub.

- **Checking GitHub:** fetch and pull the latest (`git fetch --all` then `git pull --ff-only`) **at most once every two days** while working on the code, not before every change. When you do, tell the owner if there are new commits from someone else and what they changed. (Tip: `git log -1 --format=%cr origin/<branch>` and the age of `.git/FETCH_HEAD` show when it was last checked.)
- **Pushing:** never force-push and never discard someone else's commits. If a push is rejected because GitHub moved on, merge those changes in, then push.
- If someone else's change breaks the game, say so and fix it forward rather than reverting their work without asking.
- **Testing:** don't run the game in a browser to confirm every change. Only do it when the owner asks, when they report a problem, or when a change is complex enough that it's genuinely needed. A quick syntax check is fine: `for f in js/*.js; do node --check "$f"; done` (`node --check js/*.js` only checks the first file).
- **Publishing:** GitHub Pages serves the `claude/android-boxing-game-dsq6ph` branch (boxing at `/Bkb/`, the bus game at `/Bkb/bus/`, Road Rumble at `/Bkb/road/`, Tractor Tippin' at `/Bkb/tip/`). Work only goes live once it's on that branch, so when you finish, get it there too (merge or fast-forward, never force-push).
- The game is plain HTML/JS with no build step: open `index.html`, scripts are in `js/`, recorded audio in `audio/`.
- **Cache-busting:** after changing any file in `js/` or `audio/`, bump the `?v=` number on the script tags in `index.html` and on the clip URL in `js/audio.js`, or phones may keep running the old copy.
- **Bus Driver** (`bus/`) is a separate kids' game with its own `index.html` and `bus/js/`. Same rules apply there: after changing anything in `bus/js/`, bump the `?v=` numbers on its script tags in `bus/index.html`.
- Bus Driver's school voice is generated clips in `bus/audio/voice/`. After changing `PROFILES` (the players) or the word lists in `bus/js/school.js`, rerun `bus/tools/make_voice.py` and bump `VOICE_VERSION` in `school.js`.
- **Road Rumble** (`road/`) is a separate 3D motorbike combat racer (three.js and PeerJS are vendored in `road/lib/`; no build step, but it must be served over http, not `file://`). Same rules: after changing anything in `road/js/`, bump the `?v=` numbers on its script tags in `road/index.html`. Online play goes through PeerJS's free public server; to test it locally run a PeerServer and add `?peerhost=127.0.0.1&peerport=9000` to the URL. Traffic and roads are generated from a seed on both machines, so anything that changes them must stay deterministic (use `RR.rng`, never `Math.random`, in `track.js`).
- **Tractor Tippin'** (`tip/`) is a separate 3D Cars-style farm game (sneak up, honk, tip tractors, escape Thrasher the combine; 1-2 players, split screen or online). It has no `lib/` of its own: it loads three.js and PeerJS from `../road/lib/`, so don't move or delete those. Same rules: after changing anything in `tip/js/`, bump the `?v=` numbers on its script tags in `tip/index.html`. Farms are generated from each level's fixed seed on both machines, so keep farm generation deterministic (`TT.rng`, never `Math.random`, in `tip/js/farm.js` layout). The characters are original look-alikes, not copies of Disney/Pixar's (the game is public on GitHub Pages), so keep their own names.
